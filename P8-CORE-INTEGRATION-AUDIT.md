# ADSE-P8 CORE INTEGRATION AUDIT

## 1. AUTHORITY MAP

The following map identifies the production classes/functions used to establish the Engineering Truth chain for ADSE-P8.

| Stage | P8 Entity / Action | Authoritative Production Service |
| :--- | :--- | :--- |
| **Core Authorization** | `registerSystem`, `registerPlant` | `ControlRegistry` (validates `p3ArchitectureId`, `p4NodeId`, and `mbseStateId` against `MBSEBehavioralEngine`) |
| **Execution Request** | `runExecution` | `CoreExecutionAuthority.execute` (Authoritative Dispatch) |
| **Dynamic Computation** | `solve()` (Solver) | `ControlExecutionEngine.solve` (Deterministic Simulation) |
| **Execution Result** | `GenericExecutionEnvelope` | Sealed by `CoreExecutionAuthority` |
| **Independent Verification** | Stability / Boundary Gates | `CoreExecutionAuthority` (evaluates `evaluatedGates`) |
| **Evidence** | `EvidenceLeafRecord` | Generated by `CoreExecutionAuthority` |
| **Provenance** | Lineage Graph | `ProvenanceGraph` (Updated by `CoreExecutionAuthority.rebuildProvenanceForEnvelope`) |
| **Digital Thread** | P8 Node Registration | `DigitalThreadRegistry.registerNode` (P4) |
| **Persistence** | Snapshot / Reconstruction | `GenericExecutionRegistry` (IndexedDB) & `ControlRegistry.snapshot` |

## 3. P2 BEHAVIOR/STATE REUSE MAP

P8 strictly consumes semantics from **ADSE-P2 MBSE Behavioral Authority**.

- **State Validation**: `ControlRegistry.registerController` validates `mbseStateId` via `MBSEBehavioralEngine.getState()`.
- **Operating Modes**: Control laws implementation implements the behavior defined in the P2 state machine.
- **Enforcement**: Controllers referring to non-existent P2 states are REJECTED.

---

## 4. P4 DIGITAL THREAD API MAP

Every P8 entity registration triggers a corresponding P4 entry:

- `ControlRegistry.registerSystem` → `DigitalThreadRegistry.registerNode` (with `ThreadNodeType.MBSEElement` specialization).
- Architecture defined via `ControlArchitectureEngine` establishes configuration edges.

---

## 5. P5/P6/P7 BINDING MAP

P8 establishes strict cross-domain context through explicit ID bindings:

- **Structural (P5)**: `p5StructuralId` in `ControlledPlant` links to `StructuralElementRegistry`.
- **Thermal (P6)**: `p6ThermalContextId` in `ControlSystem` links to `ThermalRegistry`.
- **Power (P7)**: `p7PowerContextId` in `ControlSystem` links to `PowerRegistry`.

---

## 6. EXECUTION BOUNDARY

The `ControlExecutionEngine` acts as the **Domain Solver**.

- **Pattern**: `runExecution` prepares a `CoreExecutionRequest` and dispatches to `CoreExecutionAuthority.execute`.
- **Boundary**: P8 dispatches; Core executes, verifies, and seals.
- **Truth**: Solver results are NEVER canonical truth until they exist in a sealed envelope.

---

## 7. VERIFICATION BOUNDARY

- **Core Gates**: Integrity and Precision are owned by the Core.
- **Domain Gates**: P8 `solve` provides stability findings which the Core wraps into the verification evidence.
- **Independence**: Verification result is part of the `GenericExecutionEnvelope` which is immutable and sealed.

---

## 8. PERSISTENCE BOUNDARY

- **Truth Persistence**: `GenericExecutionRegistry` stores all verified envelopes.
- **Structural Persistence**: `ControlRegistry` manages the authoritative system models.
