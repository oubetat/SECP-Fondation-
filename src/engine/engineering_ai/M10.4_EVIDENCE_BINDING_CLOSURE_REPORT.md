## 4. Architecture: The M10.4 Evidence Binding Pipeline

M10.4 introduces `EngineeringAIEvidenceBinder.ts`, anchoring AI outputs into the unified SECP evidence and twin graph:

```
[ EngineeringAI Inference ] ───► [ IndependentAIVerifier ] ───► [ HardenedVerificationReport ]
                                                                             │
                                                                             ▼
                                                           [ EngineeringAIEvidenceBinder ]
                                                                             │
                                     ┌───────────────────────────────────────┴───────────────────────────────────────┐
                                     ▼                                                                               ▼
                          [ Deterministic Evidence ID ]                                                   [ AIEvidenceEnvelope ]
                      (EV-AI-<hash of canonical inputs>)                                                  - subject: (rev, geom)
                                                                                                          - verification: ADVISORY_EVIDENCE
                                                                                                          - provenance: (model, ctx, exec)
                                                                                                          - contentHash: canonical sha256
                                                                                                          - isCanonicalRelease: FALSE
                                                                                                                     │
                                                                             ┌───────────────────────────────────────┘
                                                                             ▼
                                                            [ TwinEvidenceGraphEngine ]
                                                            - Node: VERIFICATION_RESULT
                                                            - Edge: VERIFIES ──► AI-INF
                                                            - Edge: DEPENDS_ON ──► REV
                                                            - Updated Merkle Root Hash
```

### 4.1 Governing Invariants of `EngineeringAIEvidenceBinder`
1. **Deterministic Identity**: `computeEvidenceId` derives identity purely from canonical model hash, context hash, execution hash, dissimilar digest, and canonical revision hash.
2. **Zero-Trust Memoization**: All hashes are recomputed and validated against the clean-room `IndependentVerificationSerializer`.
3. **Authority Invariance**: The envelope is hardcoded with `isCanonicalRelease: false` and `authorityTag: 'ADVISORY_EVIDENCE'`. Any attempt to claim release authority or mutate canonical engineering state is rejected.
4. **Graph Integration**: Automatically binds verification nodes to inference nodes (`VERIFIES`) and revision nodes (`DEPENDS_ON`) within `TwinEvidenceGraphEngine`, updating the cryptographic Merkle root.
5. **Zero Identity Drift**: Serialization and rehydration (`serializeEnvelope` / `rehydrateAndValidate`) perform bit-for-bit re-verification of all digests and context bindings.
